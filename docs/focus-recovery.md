# 专注中断恢复

日期：2026年10月21日

## 自动保存

正在计时和休息时每5秒保存一次状态；开始、暂停、继续、结束、切换轮次和拦截次数变化时立即保存。自动保存包含计时方式、有效区间、关联项目与待办、暂停／休息剩余时间、番茄轮次，以及本次应用和网站规则。

正计时累计有效专注满24小时自动结束并保存，不进入休息，解除限制与常亮；提示状态保存在`focus.limitNotice`，再次打开软件时提示一次。

已完成的专注仍按原流程写入正式记录。正常结束或明确退出后清除自动保存；关闭到托盘继续计时。

## 重新打开

发现未处理的计时时显示恢复窗口，用户选择前不自动计时或启动严格限制，也不能开始另一段专注。暂时关闭恢复窗口后，可从主窗口顶部的“恢复上次专注”再次打开；退出软件会保留待处理状态。

- **继续专注**：保留原会话、已保存时长、待办及严格规则，从确认时继续；中断期间不计入有效专注。
- **恢复暂停／继续休息**：保留最后保存的剩余时间，从确认时继续该阶段。番茄循环保留原轮次，不补跑关闭期间错过的轮次。
- **保存并结束**：仅保存中断前已确认的部分，记录标记为“中断后保存”。有效专注不足10秒的部分仍不计入。
- **放弃**：确认后移除未完成计时，已保存的正式记录保留。

正式记录与自动保存共用会话ID。重开时若正式记录已存在，不会用较早的自动保存重复计入或覆盖它。记录保存失败时保留恢复入口，可以重试。

## 实现

`FocusCheckpoint`由`FocusTimer`捕获和恢复；`MainViewModel.Recovery.cs`在SQLite设置`focus.checkpoint`中保存状态。复用现有设置和正式记录事务，不新增表。自动保存随本地数据库备份保留。

## 当前边界

崩溃或断电后只能恢复最近一次成功自动保存的部分，最后一小段尚未保存的时间无法确认。自动保存失败时在主窗口显示错误，计时继续运行并在后续刷新时重试。
